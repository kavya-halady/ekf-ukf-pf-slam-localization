# TurtleBot4 Localization Benchmark: EKF vs UKF vs Particle Filter (Cartographer Ground Truth)

## Overview

This project implements and benchmarks three classical robot localization
algorithms — **Extended Kalman Filter (EKF)**, **Unscented Kalman Filter
(UKF)**, and **Particle Filter (PF)** — on real sensor data collected from a
TurtleBot4 running **Cartographer SLAM**. Cartographer's `map → base_link`
transform is used as ground truth, against which each filter's estimated
trajectory is compared using **RMSE (Root Mean Square Error)** in position
and yaw, across multiple linear speeds and motion patterns (straight-line,
circular, rectangular).

The pipeline covers the full loop: teleop-driven data collection → SLAM →
ground truth extraction from TF → running each filter on the recorded bag →
quantitative + visual error analysis.

## What this project does

1. **Data collection:** Drives a TurtleBot4 via teleop while Cartographer SLAM
   runs, recording a ROS 2 bag of `/odom`, `/scan`, `/tf`, `/tf_static`, `/imu`.
2. **Ground truth extraction:** Extracts the `map → base_link` transform from
   the recorded bag's TF data (Cartographer's SLAM-corrected pose) and
   converts it to CSV — this serves as ground truth, since it's corrected by
   loop closure and scan matching rather than relying on raw, drift-prone
   odometry.
3. **Filter estimation:** Runs each filter (EKF / UKF / PF) on the same bag
   data (odometry + control inputs) to estimate the robot's trajectory
   independently of Cartographer.
4. **Error analysis:** Interpolates ground truth to each filter's timestamps,
   computes position RMSE, X/Y RMSE, yaw RMSE, MAE, and max error, and
   generates trajectory + error plots for each filter and each run.
5. **Multi-speed comparison:** Repeats the above across a range of linear
   speeds (0.2–1.6 m/s) and trajectory shapes (line, circle, rectangle) to
   see how filter accuracy changes with robot speed and motion type.

## Data flow

```
Teleop (keyboard) → TurtleBot4 hardware
        │
        ▼
Cartographer SLAM  ──►  /odom, /scan, /tf, /tf_static, /imu
        │
        ▼
ros2 bag record  ──►  data/speed_X.X  (raw bag)
        │
        ├──► extract_tf_from_bag.py / tf_bag_to_csv.py
        │        └──► ground_truth/gt_speed_X.X.csv   (map → base_link, Cartographer-corrected)
        │
        └──► ekf_rmse.py / ukf_rmse.py / pf_rmse.py
                 └──► filter estimate vs ground_truth CSV
                          └──► RMSE results (.txt) + error plots (.png)
```

## Prerequisites

- Ubuntu 22.04 with ROS 2 Humble
- TurtleBot4 (or compatible diff-drive robot) with Cartographer SLAM configured
- `cartographer_ros`, `teleop_twist_keyboard`, `rosbag2`
- Python 3.10 with:
  - `numpy`, `scipy`, `matplotlib`, `PyYAML`, `Pillow`
  - `transformations` (quaternion ↔ Euler conversions)
  - `rclpy`, `rosbag2_py`, `rosidl_runtime_py` (for reading bag files)

Install Python dependencies:

```bash
pip install numpy scipy matplotlib pyyaml pillow transformations
```

## Setup & build

```bash
cd cartographer_ws_new
source /opt/ros/humble/setup.bash
colcon build --symlink-install
source install/setup.bash
```

## Step-by-step: running the full pipeline

### 1. Launch SLAM

```bash
ros2 launch cartographer_ros cartographer.launch.py
```

### 2. Drive the robot (teleop)

```bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard
```

### 3. Record a bag

```bash
ros2 bag record /odom /scan /tf /tf_static /imu -o data/speed_0.5
```

Repeat for each speed/trajectory you want to test (e.g. `speed_0.2`,
`speed_0.8`, `speed_1.0`, circular/rectangular runs, etc.).

### 4. Extract ground truth from the bag

```bash
python3 cartographer_ws_new/extract_tf_from_bag.py --bag data/speed_0.5
python3 cartographer_ws_new/tf_bag_to_csv.py --bag data/speed_0.5 --out ground_truth/gt_speed_0.5.csv
```

This pulls the Cartographer-corrected `map → base_link` transform out of the
bag and writes it as a ground-truth CSV (`time, x, y, z, qx, qy, qz, qw`).

### 5. Run each filter and compute RMSE

**EKF:**
```bash
python3 ekf_rmse.py --bag data/speed_0.5 --ground_truth ground_truth/gt_speed_0.5.csv --map_yaml map.yaml
```

**UKF:**
```bash
python3 ukf_rmse.py --bag data/speed_0.5 --ground_truth ground_truth/gt_speed_0.5.csv --map_yaml map.yaml
```

**Particle Filter:**
```bash
python3 pf_rmse.py --bag data/speed_0.5 --ground_truth ground_truth/gt_speed_0.5.csv --map_yaml map.yaml
```

Each script:
- loads the occupancy grid map (`map.yaml` / `map.pgm`) for visualization,
- reads odometry + control inputs from the bag,
- runs the corresponding filter (EKF / UKF / 100-particle PF with low-variance
  resampling),
- interpolates ground truth to the filter's timestamps,
- computes RMSE (position, X, Y, yaw), MAE, and max error,
- saves results to `<filter>_rmse_results.txt`,
- saves trajectory and error-analysis plots (`<filter>.png`,
  `<filter>_error_analysis.png`).

### 6. Repeat across speeds

```bash
python3 ekf_rmse.py --bag data/speed_0.2 --ground_truth ground_truth/gt_speed_0.2.csv --map_yaml map.yaml
python3 ekf_rmse.py --bag data/speed_1.0 --ground_truth ground_truth/gt_speed_1.0.csv --map_yaml map.yaml
```

Do the same for `ukf_rmse.py` and `pf_rmse.py` to build a full picture of how
each filter's accuracy changes with speed.

## Output

- **Numeric results:** `ekf_rmse_results.txt`, `ukf_rmse_results.txt`,
  `pf_rmse_results.txt` — position RMSE, X/Y RMSE, yaw RMSE (rad + deg), MAE,
  max error, mean/std of X and Y error.
- **Plots:** trajectory overlay (filter estimate vs. ground truth vs. map),
  position error over time, X/Y error over time, error histogram.

## Notes

- Always match the bag and ground-truth file for the same run — mixing runs
  will silently produce meaningless RMSE numbers.
- Ground truth comes from Cartographer's `map → base_link` transform, not raw
  odometry, since SLAM correction removes most drift that would otherwise bias
  the comparison in the filters' favor.
- The particle filter uses 100 particles with low-variance resampling,
  triggered when the effective particle count drops below `NP/2`.

## Status / limitations

- Ground truth quality depends on Cartographer's SLAM accuracy (map quality,
  loop closures) — it is a strong reference but not a true external-motion-
  capture ground truth.
- Filters are run offline against recorded bag data, not online/real-time.
- Results are specific to the TurtleBot4's odometry noise characteristics and
  the tuned `Q`/`R` noise matrices in each script; retuning may be needed for
  a different robot.
